있었으므로, 상한(`max_pixels`)을 올리는 방법으로는 이 문항들의 입력이 바뀌지 않습니다. 상세 판정은

적용 대상이 아닌 1건을 더한 수입니다). 저장소에는 포함하지 않으며 팀 내부에서만 보관합니다.

같은 결론이 나왔습니다. 사람이 판정한 결과는 Paddle 우세 26장, 동률 2장, Easy 우세 1장,

EasyOCR보다 뚜렷하게 나은 엔진임을 확인했더라도, 위에서 측정한 9B·val_fold0 실험의

A와 정확도 수준은 비슷하면서도 틀리는 문항이 다르다는 점(불일치 25개)에 주목해, 결합

## 2026-09-26 Gemma-4 QLoRA (최종 제출 재변경)

위 절의 Gemma는 bf16 가중치 약 62GB가 학습 하한 82GB를 만들어서 A100 80GB 한 장으로는 학습할 수
없었습니다. 2026-09-26 밤에 가중치를 nf4로 4bit 양자화해서 올리고 LoRA adapter만 bf16으로
학습하는 방식으로 이 제약을 우회했습니다.

설정 파일은 `configs/colab_gemma4_31b_nf4_lora.yaml`이고 run-id는
`gemma4_31b_ft_nf4_v2_read_text`입니다. 학습 데이터는 A와 같은 fold 1~4의 5,358문항이고, LoRA는
r 16과 alpha 32, 학습률 1e-4, 1 epoch입니다. 양자화에서 제외한 모듈은 `model.vision_tower`와
`model.embed_vision`, `lm_head` 세 개이며, 시각 토큰 예산 1,120과 프롬프트 `v2_read_text`는 bf16
설정과 같게 두었습니다. 개인 Colab 계정의 A100 80GB에서 실행했고, preflight의 `forward_backward`가
보고한 peak VRAM은 약 32GB였습니다. 설정 파일이 계산하는 학습 하한 어림값 37.0GB와 같은
자리입니다.

판정 기준은 학습 전에 고정해 두었습니다. nf4는 가중치를 4bit로 뭉개므로 nf4 zero-shot을 기준으로
삼으면 양자화 손실을 메운 몫까지 학습의 성과로 계산하게 됩니다. 그래서 기준을 bf16 zero-shot의
fold 0 정확도 0.9695로 두고, 그보다 0.005 이상 높은 0.9745 이상이 나와야 결합 후보로 올리기로
정했습니다.

fold 0 정확도는 0.9747(1310/1344)이었고, bf16 zero-shot의 0.9695(1303/1344)보다 7문항
높았습니다. 문항 단위로는 17문항이 개선되고 10문항이 악화되었으며 McNemar 검정의 p값은
0.248이어서 표본 변동과 구분되지 않습니다. 다만 사전 기준 0.9745는 통과했습니다. 틀린 문항에서
고른 선지에 실어 준 확률의 평균 margin은 zero-shot의 0.904에서 0.825로 내려가, 과신도 함께
누그러졌습니다.

fold 0에서 A(1302문항)와 Gemma 두 모델만으로 가중치를 옮겨 가며 정답 수를 재고, zero-shot
예측을 쓴 경우와 QLoRA 예측을 쓴 경우를 나란히 놓았습니다. 괄호 안은 A 단독 대비 정답 수의
증감입니다.

| Gemma 가중치 | A + Gemma zero-shot | A + Gemma QLoRA |
|---|---|---|
| 0.30 | 1305 (+3) | 1305 (+3) |
| 0.35 | 1307 (+5) | 1307 (+5) |
| 0.40 | 1310 (+8) | 1308 (+6) |
| 0.45 | 1311 (+9) | 1309 (+7) |
| 0.50 | 1307 (+5) | 1310 (+8) |
| 0.55 | 1306 (+4) | 1312 (+10) |
| 0.60 | 1305 (+3) | 1313 (+11) |

QLoRA 쪽 곡선이 0.60까지 단조롭게 오르지만, 이 상승은 결합의 이득이 아닙니다. QLoRA 단독
정확도가 이미 1310문항이어서, 가중치를 올릴수록 결합 예측이 Gemma 단독 예측으로 수렴하면서 그
값에 가까워진 것입니다. 두 곡선의 정점끼리 견주면 zero-shot이 0.45에서 1311문항, QLoRA가
0.60에서 1313문항이므로 차이는 2문항뿐입니다.

보완성도 줄었습니다. A만 맞힌 문항과 Gemma만 맞힌 문항, 둘 다 틀린 문항의 개수가 zero-shot에서
19개와 20개와 22개였는데 QLoRA에서는 12개와 20개와 22개로 바뀌었습니다. 학습이 개선한 자리가
대부분 A도 이미 맞히던 문항이어서 Gemma가 A를 닮아 갔고, 둘 다 틀리는 22문항은 하나도 줄지
않았습니다.

test 결과는 fold 0의 판정과 달랐습니다. QLoRA 예측과 zero-shot 예측이 test 6,714문항에서 같은

가운데 약 88문항에 그쳤습니다.

Gemma 전체 QLoRA 예측으로 통째로 바꾼 결합입니다. Public 점수는 0.97676으로 ⑳보다 6문항
낮았고, ⑳과 답이 갈린 문항은 28개였습니다. 제출 파일의 sha256 전체 값은

최종 선택을 바꾸는 기준은 학습을 걸 때 "⑳의 0.97765를 넘어야 한다"로 정해 두었습니다. ㉒는
동점에 그치고 ㉓은 오히려 6문항 낮게 나와 둘 다 그 기준에 못 미쳤으므로 채택하지 않았고,
최종 제출은 1순위 ⑳과 2순위 ⑲로 그대로 두었습니다.

이 결과는 27B에서 전체 데이터 학습 B가 fold 1~4 학습 A를 넘지 못했던 것과 같은 방향입니다. 이
데이터에서 결합으로 얻을 수 있는 이득은 계열이 다른 모델 하나를 학습해 섞는 데까지였고, 같은
계열 안에서 변형을 더 얹는 조작은 전체 데이터 학습과 배깅, dev 세트 추가, epoch 연장, seed 변경,
그리고 세 번째 재료를 전체 학습 모델로 통째로 바꾼 ㉓ 가운데 어느 것도 점수를 움직이지
못했습니다. 그래서 같은 계열 변형을 시험하는 실험은 여기에서 종료했습니다. 다만 아직 시험하지
않은 다른 계열 재료인 InternVL3.5-38B의 nf4 QLoRA 학습을 마지막으로 한 번 더 진행했으며, 그
결과는 아래 "2026-09-27 InternVL3.5-38B QLoRA" 절에 정리했습니다.

## 2026-09-27 InternVL3.5-38B QLoRA (기각)

여기까지 결합에 들어간 재료는 Qwen3.5-27B 두 개와 Gemma-4-31B-it 하나였습니다. 계열이 다른 모델
하나를 넣었을 때에만 점수가 올랐으므로, 아직 써 보지 않은 네 번째 계열을 마지막으로 한 번 더
시험했습니다. 고른 모델은 `OpenGVLab/InternVL3_5-38B-HF`(revision
`7c830fc25e874f9a861087e3c70587f2b9b555f3`, apache-2.0, bf16 스냅샷 76.8GB)이며, 시각 인코더가
InternViT-6B이고 언어 backbone이 Qwen3-32B여서 시각 쪽이 Qwen 계열과도 Gemma 계열과도
다릅니다.

설정 파일은 `configs/colab_internvl35_38b_nf4_lora.yaml`이고 run-id는
`internvl35_38b_ft_nf4_v2_read_text`입니다. 정밀도는 nf4, 어림 가중치 크기 `weights_gb`는 45로
두었고, 양자화에서 제외한 모듈은 `model.vision_tower`와 `model.multi_modal_projector`,
`lm_head` 세 개입니다. 해상도를 정하는 값인 `processor_kwargs.max_patches`를 4로 두어 448 타일
다섯 장과 시각 토큰 1,280개를 썼습니다. 프롬프트는 `v2_read_text`, LoRA는 r 16과 alpha 32,
학습률 1e-4, 1 epoch이며 LoRA target은 언어 쪽 448개입니다. 학습 데이터는 A와 같은 fold 1~4의
5,358문항입니다.

| 항목 | 실측값 |
|---|---|
| optimizer step 수 | 670 |
| step당 시간 | 32.6초 |
| 학습에 걸린 시간 | 6시간 6분 (UTC 2026-09-26 09:26:30 시작, 15:32:05 종료) |
| 학습 peak VRAM | 52.9GB |
| 마지막 loss의 EMA | 0.155 |
| GPU | 개인 Colab 계정의 A100 80GB |

설정 파일에서 미리 잡아 둔 어림값은 약 42초/step에 peak VRAM 55GB에서 57GB였는데, 실제로는
32.6초/step에 52.9GB로 어림값보다 빠르고 가볍게 끝났습니다.

판정 기준은 학습을 걸기 전에 설정 파일에 적어 두었습니다. 첫째로 fold 0 단독 정확도가
0.9635(1295/1344) 이상이어야 하고, 둘째로 A와 Gemma의 결합에 이 예측을 넣었을 때 fold 0에서
3문항 이상 늘어야 합니다.

fold 0 단독 정확도는 0.9315(1252/1344)였습니다. 첫째 기준에 43문항이 모자라고 A의 1302문항과는
50문항 차이입니다. 파라미터를 8B에서 38B로 키웠는데도 LoRA 학습을 마친 InternVL3.5-8B의 0.9345와
같은 수준에 머물렀습니다. 틀린 문항에서 고른 선지에 실어 준 확률의 평균 margin은 0.711로,
Gemma zero-shot의 0.904나 Gemma QLoRA의 0.825보다 낮습니다.

첫째 기준에서 이미 탈락했지만 결합도 함께 재 보았습니다. 기준으로 삼은 값은 A와 Gemma QLoRA를
0.6 대 0.4로 섞은 fold 0 1308문항이고, Gemma의 몫을 덜어 InternVL에 주는 방식으로 가중치를
옮겼습니다.

어느 가중치에서도 기준 1308을 넘지 못했으므로 둘째 기준도 통과하지 못했습니다. 문항 단위로 보면
계열이 다르다는 전제 자체는 성립했습니다. A와 Gemma가 둘 다 틀린 22문항 가운데 InternVL이 맞힌

셋이 모두 틀린 문항은 17개여서, 새로 가져오는 몫보다 확률 평균을 끌어내려 잃는 몫이 훨씬
컸습니다.

두 기준을 모두 넘지 못했으므로 기각했고, 약 3.7시간이 드는 test 추론은 수행하지 않았습니다.
InternVL 계열은 8B와 38B 모두 이 과제의 한국어 OCR에 맞지 않는다고 판단합니다. 계열이 다르기만
해서는 결합 재료가 되지 못하고, 단독 강도가 적어도 A 수준에는 닿아야 결합에서 이득이 난다는
것이 이 실험으로 확인되었습니다. 이것으로 시도할 수 있는 실험을 모두 마쳤고 GPU 실험을
종료했습니다. 최종 제출은 1순위 ⑳(0.97765)과 2순위 ⑲(0.97616)로 확정했습니다.

## 2026-09-27 TTA 재시도와 GPU 없는 변형 (기각)

InternVL3.5-38B QLoRA를 기각한 다음, A의 재료가 nf4 QLoRA로 바뀐 김에 선택지 순열 TTA
예측으로 결합을 다시 만들어 두는 편이 나을지 마지막으로 한 번 더 확인했습니다. A의 선택지
순열을 4회 평균한 예측을 "A_tta4"라고 부르며, ⑧에 같은 TTA4를 적용한 예측은 "B_tta4"라고
부릅니다.

㉕는 A_tta4 0.3과 ⑧ 0.3과 Gemma QLoRA 0.4(fold 1~4 학습, ⑳의 세 번째 재료와 동일)를 확률
가중 평균으로 섞은 결합입니다. Public 0.97676이며, ⑳(0.97765)보다 6문항 낮았고 ⑳과 답이
갈린 문항은 14개였습니다. 제출 파일의 sha256 전체 값은
`53264583bac9aec52981670543225fb49affba542c9c9504a35952de3b8b9f69`입니다.

㉖은 A_tta4 0.3과 B_tta4 0.3과 Gemma QLoRA 0.4를 섞은 결합입니다. 마찬가지로 Public
0.97676이며, ⑳과 답이 갈린 문항은 26개였습니다. 제출 파일의 sha256 전체 값은
`15ed1e8ecbdbe8e56ddcff485efbd5f69f831e014a5a4b47c9e89b468e3d4066`입니다. ㉕와 ㉖ 모두
pandas로 확률을 직접 가중 평균해서 만든 파일이며, `scripts/blend_preds.py`로는 그대로
재현되지 않는 조합입니다.

fold 0에서는 A를 TTA 예측으로 바꾸면 A와 Gemma QLoRA 결합(기준 1308문항)의 정답 수가 1308에서
1313으로 5문항 늘었습니다. 그런데도 test에서는 오히려 낮아졌으므로, fold 0의 이득이 test에서
뒤집힌 사례입니다. 2026-09-23과 2026-09-24에 이미 확인했던 A_tta + ⑧(test 0.97050, ⑩의
0.97110보다 낮음)과 A_tta4 + B_tta4(test 0.96991)에 이어 세 번째 사례이며, 이로써 TTA는
완전히 기각을 재확인했습니다.

같은 날 GPU 없이 fold 0에서 재 본 다른 결합 변형(A와 Gemma QLoRA 결합, 기준 1308문항 대비)도
모두 ±2문항 안에 그쳐 test 제출은 하지 않았습니다. 기하 평균은 1307~1310문항, 다수결은
1308문항, 순위 평균은 1305문항, Gemma 자리에 zero-shot 예측을 함께 섞는 방식은 1310~1311문항이었습니다.

이것으로 저희가 시도할 수 있는 카드를 모두 소진했습니다. 최종 제출은 그대로 1순위
⑳(0.97765), 2순위 ⑲(0.97616)로 확정합니다.
