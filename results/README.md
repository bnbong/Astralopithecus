## fla 가속 커널 설치 전후 비교 (A100 80GB, bf16, LoRA)

| 항목 | fla 없음 (2026-09-21 낮, TF32 켬) | fla 0.5.2 (2026-09-21 밤) |
|---|---|---|
| 학습 microbatch | 7.3초 | 1.50초 (prepare 0.035초 / compute 1.46초) |
| preflight optimizer step | 측정하지 않음 | 11.99초 |
| 본 학습 optimizer step | 58초 | 13.5초 |
| 문항당 추론 | 측정하지 않음 | 0.41초 |
| peak VRAM | 측정하지 않음 | 55.4GB (preflight) / 57.0GB (학습) |

본 학습의 optimizer step이 58초에서 13.5초로 줄어 약 4.3배 빨라졌습니다. 두 측정은 같은 A100 80GB에서
27B를 bf16으로 올리고 LoRA r=16, grad_accum 8로 돌린 결과입니다. transformers 5.16은 Qwen3.5 Gated
DeltaNet의 `chunk_gated_delta_rule`을 Hub 커널로 부르는데, `fla`가 없으면 예외 없이 PyTorch 참조
구현으로 내려가기 때문에 속도를 직접 재 보기 전에는 알아채기 어렵습니다. 상세한 추적 과정은
[`docs/discussion_fla_kernel.md`](../docs/discussion_fla_kernel.md)에 있습니다.

## fold 0 ft_p2 오답 56문항 라벨 점검 (2026-09-22)

27B 학습 모델 두 종(ft_v1, ft_p2)이 공통으로 틀린 47문항에 ft_p2만 틀린 9문항을 더한 56문항을 수빈 님이
이미지와 선택지를 대조해 점검했고, 같은 47문항을 창혁 님이 독립적으로 분류했습니다. 두 판정을 합친
consensus 분포는 라벨 문제 35건, 모델 오류: 작은 글자 12건, 모델 오류: 추론 8건, 미점검 1건입니다.

라벨 문제 35건은 fold 0의 2.60퍼센트이고, 모델이 고칠 수 있는 오류는 20건(1.5퍼센트)입니다. 고칠 수
있는 최대 21건을 되돌린다고 보면 추정 상한은 (1288 + 21) / 1344 = 0.9740입니다. 이 값은 라벨 문제
35건을 모두 제외한 추정치이며, 애매함으로 분류한 28건 가운데 일부를 모델이 맞힐 가능성도 남아
있습니다. 공통 오답 47문항 기준으로 라벨 오류를 보정한 정확도(하한값)는 ft_v1이 1292/1321 = 0.9780,
ft_p2가 1294/1321 = 0.9796입니다. 상세 판정은 `artifacts/data/fold0_label_check_27b.csv`,
`artifacts/data/fold0_error_types_27b.csv`, `artifacts/data/fold0_label_check_27b.md`에 있습니다.

## 외부 OCR 결합 기각 (2026-09-22)

EasyOCR로 뽑은 텍스트를 프롬프트에 붙이는 방식(p4)을 9B에서 재 보니 정확도가 p2의 0.9479에서
0.9308로 떨어졌고, 문항당 추론 시간은 0.66초에서 1.08초로 늘었습니다. 27B 오답 가운데 OCR이 글자를
읽어 낸 14건에서는 개선 0건, 불변 11건, 회귀 3건이었고, 작은 글자·흐린 글자 유형 19건에서 EasyOCR의
성공률은 21퍼센트(4/19)에 그쳤습니다. 모델이 읽지 못하는 글자는 OCR도 읽지 못하므로, 병목은 모델에
들어가는 픽셀에 있다고 판단해 OCR 결합을 기각했습니다. 작은 글자로 틀린 12문항은 모두 기존 상한
1,048,576픽셀 아래에 있었으므로, `max_pixels`가 아니라 `min_pixels`를 올리는 확대를 다음 실험으로
정했습니다.

dev 이미지 30장으로 PaddleOCR과 EasyOCR을 비교한 결과는 Paddle 우세 26장, 동률 2장, Easy 우세 1장,
둘 다 실패 1장이었습니다. 엔진을 바꾸어도 위 결론은 바뀌지 않는다고 보았습니다. 비교 데이터는
`artifacts/data/ocr_engine_comparison_30.csv`에 있습니다.
